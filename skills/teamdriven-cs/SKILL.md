# 무가 시딩 CS 자동화

이 패키지는 기존 CS 판단 흐름을 공유하는 **초안·상태 판단용 스킬**이다. 발송 엔진·스케줄러·영속 저장소는 포함하지 않는다. 설치를 운영 자동 발송 활성화로 처리하지 않는다. 외부 DM·메일·Slack 발송, 발주·출고·계약·예산 승인을 실행하지 않는다.

## 첫 설정

프로젝트 지침과 현재 연결에서 아래를 확인한다. 확인된 값은 다시 묻지 않고 부족한 항목만 받는다.

- 실제 업무 계정·담당자·사용 채널 및 대화 조회 도구
- 최신 CS 유형 DB와 공통 운영 기준의 Notion URL
- 승인된 협업 가이드 원문 위치
- 비공개 처리 이력 위치와 담당자 확인 요청을 남길 위치

공유 저장소에 실제 대화·후보 명단·수령정보·연락처·토큰을 넣지 않는다. 설치한 사람의 계정·권한으로 자료 접근 가능 여부를 따로 확인한다. 브라우저나 앱 사용은 현재 도구가 지원하고 사용자가 허용한 범위에서만 수행한다.

## 판단 전

최신 Notion 공통 기준과 해당 질문의 `사용 기준 → 답변 → 처리 기준 → 답변 상태`를 읽는다. 고정 가이드는 승인 원문 그대로 사용한다. 접근 불가·정책 충돌·원문 누락이면 임의 조건이나 답변으로 메우지 않고 담당자 확인으로 남긴다. 과거 수량·기간·가격·재고·공구 일정은 현재 정책으로 복사하지 않는다.

대화 입력·출력은 [references/input-output-contract.json](references/input-output-contract.json)을 참고한다. 이는 연결용 예시 규격이며 실제 서비스에 해당 필드나 API가 존재한다고 가정하지 않는다.

## 대화 처리

1. 같은 계정의 연속된 새 메시지를 묶어 최초 제안, 이전 조건·수락·거절, 주소, 가이드, 사람 답변과 처리 이력을 읽는다.
2. 최초 제안이 `제품 제공 + 개인 계정 릴스 제작·업로드`일 때만 적용한다. 메가셀러·마켓 테스트·유가·행사는 구분하고 불명확하면 담당자 확인으로 둔다.
3. 실제 메시지 ID와 처리 이력을 대조한다. 사람이 이미 답했으면 `human_handled_skip`, 같은 메시지가 처리됐으면 `duplicate_skip`으로 두고 답장을 반복하지 않는다. 읽음 여부만으로 처리 완료를 판단하지 않는다.
4. 질문·조건을 빠짐없이 나누어 승인 기준을 적용하고 자연스러운 통합 답장 하나를 만든다. 인사·감사·수락 확인은 반복하지 않는다.
5. 주소만 회신했고 미해결 조건·거절이 없다면 배송정보 취합과 미전달 가이드 초안을 준비한다. 주소와 원고료·선체험 등 조건 질문이 섞이면 답변과 명확한 수락 확인이 먼저이며 `shipment_hold=true`다.
6. 감사·이모지·주소·조건부 수락만으로 조건 합의를 확정하지 않는다. 정보 요청과 승인, 가이드 발송과 실제 출고, 공동 게시자와 브랜디드 레이블을 구분한다.
7. 단백질 원료·건강 우려, 정책 부재·충돌, 경품 지원 승인 등 담당자 판단이 필요한 항목은 확인 대기로 둔다. 최신 승인된 임시 답변이 있을 때만 그 범위의 초안을 허용한다. 복합 질문에 확인 항목이 섞이면 나머지 초안과 보류 질문을 함께 제시한다.
8. 건강 우려·불만에는 웃음 표현을 쓰지 않는다. 외부 답장에 내부 판단·상태·메모를 섞지 않는다.

## 출력·검증

질문별 적용 근거, 통합 답장, 가이드 원문 필요 여부, 명시 수락 여부, 출고 보류, 담당자 확인 항목, 중복 상태와 다음 행동을 구분한다. `send_allowed=false`를 유지한다. 실제 자료를 읽은 범위와 미검토 범위도 남긴다.

설치 검증은 가상 대화로 수행한다: 주소만 회신 / 주소+원고료 문의 / 여러 질문 / 조건 안내 뒤 명시 수락 / 모호한 감사 / 담당자 확인 질문 혼합 / 사람 답변 있음 / 초안 후 새 메시지 / 같은 입력 재실행 / 과거 발송 결과 불명확. 외부 발송으로 검증하지 않는다.

## 기존 운영 엔진에 연결할 때 필요한 조건

- 실제 입력·출력 필드와 기록 위치를 대조한다. 자동화가 이미 동작 중이라고 추정하지 않는다.
- 중복 키는 `(account_id, channel, conversation_id, inbound_message_id)`로 유지한다. `draft_version`이 달라져도 같은 원문에 성공 발송을 반복하지 않는다.
- 영속 이력, 원자적 처리 잠금, 사람 답변·최신 메시지 재조회, 실제 성공 메시지 ID 확인이 필요하다. 기능이 없으면 미구현으로 남긴다.
- 새 메시지·사람 답변이 있으면 기존 초안을 취소하고 재판단한다. 발송 결과가 불명확하면 확인 전 재발송하지 않는다.
- 연결 준비·가상 검증·실제 운영 검증을 구분해 보고한다. 운영 엔진 구현·배포·자동 발송 활성화는 별도 작업이다.
