# 후보 검증과 신규 컨택

## 중복 확인

1. 프로젝트 최신 발송 원장과 사용자 제공 컨택·제외 이력을 ID로 확인한다. 오래된 후보표의 '대화 없음'보다 이후 실제 발송 기록이 우선한다.
2. 연결된 Notion 데이터 소스를 먼저 fetch하여 현재 collection URL과 스키마를 확인한다. 필요한 후보 ID·프로필 URL·실제 발송 횟수·상태만 묶어서 조회한다.
3. 프로필 URL의 대소문자, 루트 경로, /reels/, 추적값을 정규화해 ID와 URL 양쪽을 확인한다. 이름만으로 합치지 않는다. 공개적으로 확인된 본인 연결 계정도 확인한다.
4. DB 등록은 컨택이 아니다. 발송 횟수의 명시적 0과 NULL·미입력을 구분한다. 다른 업무 계정의 실제 발송도 중복이다.
5. 정확한 후보 DM을 열어 실제 이전 발신·수신을 확인한다. 기존 발신이 있으면 제외한다. 수신만 있거나 접근·로딩이 불충분하면 보류한다. Notion 일치 없음만으로 대화 없음이라 확정하지 않는다.

중복 확인 중 과거 주소·연락처·광고 코드·DM 본문을 불필요하게 출력하거나 공개 자료에 저장하지 않는다. 읽기 전 안읽음 여부를 기록하고 복원 절차를 따른다.

## 공개 수치

- 공개 검색·관련 게시물·팔로잉 등 실제 관찰한 발견 경로를 남긴다. 아이디 배열이나 프로필 URL을 지어내서 탐색하지 않는다.
- 프로필 ID와 팔로워를 함께 확인한다. 팔로잉 수를 팔로워 수로 오인하지 않는다.
- 릴스 탭에서 고정 표식을 확인하고 비고정 최신 6개를 순서대로 수집한다. URL 중복과 누락을 점검한다.
- 재생 조회수와 좋아요 수를 구분한다. 1.1만은 약 11,000으로 기록한다. 게시 직후 조회수가 낮아도 임의로 그 영상을 빼지 않는다.
- 최신 비고정 릴스 본문에서 실제 게시일을 확인한다. 공동 게시물은 해당 후보의 프로필 릴스 목록과 참여 계정을 대조한다.
- 최근 콘텐츠와 공개 소개로 주제 적합성을 확인한다. 특정 영상 하나나 과거 식단 콘텐츠만으로 현재 주제를 단정하지 않는다.
- 검증 불가는 0이나 합격이 아니다. 후속 확인이 필요한 이유를 남긴다.

## 발송 직전

- 오늘 KST 날짜, 고유 신규 완료 수, 시도했지만 미확정인 건, 수동 신규 컨택 수를 대조한다. 기존 대화 회신은 신규 수에 넣지 않는다.
- 직전 발송 시각은 휘발성 변수만 믿지 말고 최신 원장의 시도·완료 시각 중 가장 늦은 값을 다시 읽어 확인한다. 그 시각으로부터 60초가 지난 뒤 전송하고, 과거 간격 위반을 발견해도 원장을 고쳐 숨기지 않는다.
- 수동 수가 이미 확인됐고 새 충돌 근거가 없으면 반복 질문하지 않는다. 다른 새 발신이 보이면 기존 회신인지 신규 제안인지 먼저 구분한다.
- DM 검색에서 '일치하는 메시지'와 '계정' 결과를 구분한다. 비슷한 ID가 여러 개면 실제 계정과 헤더 링크로 최종 확인한다.
- 선택 직후에는 이전 대화나 빈 화면이 잠깐 남을 수 있다. 정확한 헤더 뒤 독립 관찰에서 본문 로딩을 확인한다. article 개수 0만으로 빈 대화를 확정하지 않는다. 프로필 보기와 빈 작성창만 있고 날짜·메시지가 없는지 확인한다.
- 공개 개인 이름의 성·이름이 명확하면 성을 제외한다. 활동명은 임의로 줄이지 않는다. 아이디에서 이름을 만들지 않는다.
- 승인 contact.txt의 [호칭]만 바꾸고 입력값 전체와 정확한 수신자를 다시 대조한다.
- 보내기 전에 ID·원문·시도 시각을 저장한다. 클릭 후 대기 상태면 재클릭하지 않는다.
- 완료는 정확한 수신자, 발신 메시지, 전송 중 표시 해제, 빈 입력창 등 실제 화면에서 확인한 뒤 기록한다. 원문 일치는 입력 시점에서 검증한다.

## 실행 원장

기존 원장 형식을 보존한다. 새 원장은 JSON 배열 또는 records 배열을 가진 객체를 쓸 수 있다. 각 발송 건의 권장 필드:

```json
{
  "id": "example",
  "dateKST": "YYYY-MM-DD",
  "givenName": null,
  "body": "실제로 입력한 승인 원문",
  "status": "전송 시도",
  "attemptAt": "시간대가 포함된 ISO-8601 시각",
  "confirmedAt": null,
  "evidence": null
}
```

완료 검증 후 status를 '발송 완료'로 바꾸고 confirmedAt과 실제 확인 근거를 기록한다. 결과가 불명확한 시도도 보존하고 미확정 목록에 둔다. 삭제해서 다시 보내지 않는다.
