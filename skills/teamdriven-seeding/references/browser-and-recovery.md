# 브라우저 사용과 회고

환경에서 제공하는 브라우저·컴퓨터 사용 도구의 실제 안내와 지원 API를 먼저 읽는다. 로그인 세션이 있다고 가정하거나 숨은 API·네트워크로 UI를 우회하지 않는다.

## 확인된 함정

- DM 헤더가 바뀌어도 본문 article은 이전 대화의 것이 잠깐 남을 수 있다. 반대로 기존 대화가 처음엔 비어 보일 수도 있다. 독립 관찰과 본문 범위 검증이 필요하다.
- 대화 범위를 읽을 때 받은편지함 전체가 섞이지 않게 한다. 왼쪽 목록의 '몇 분 전 발신'을 선택한 후보의 기존 발신으로 오인하지 않는다.
- 검색 결과의 같은 표시명·유사 ID·메시지 일치를 실제 수신자로 혼동하지 않는다. 헤더 프로필 링크가 최종 기준이다.
- 메뉴·검색 결과·스크롤은 직전 화면이 잠시 남을 수 있다. 한 번의 오래된 ref·count를 완료 근거로 쓰지 않는다.
- 작은 0.01페이지 스크롤이 연결 중단을 일으킨 전례가 있다. 적정 스크롤 후 새 관찰을 하고 같은 실패를 반복하지 않는다.
- 과거 rg 배치 검색이 파일이 있는데도 빈 결과를 낸 전례가 있다. 명시적 파일 목록과 구조화 JSON 검증으로 대조하고 빈 검색 결과만으로 중복 없음이라 단정하지 않는다.
- 고정 표시·릴스 조회수·게시 날짜·계정 규모를 후보 확정 전에 함께 확인한다. 초기 기준 누락은 재수집 비용을 크게 만든다.

## 사용량 절약

- 원장·이미 확인한 공개 근거·제외 사유·발견 경로를 재사용한다. 변경 근거나 불일치 없이 같은 후보를 반복 탐색하지 않는다.
- Notion은 필요한 후보의 ID·정규화 URL·발송 횟수를 묶어 확인한다. 모든 컬럼이나 전체 DB를 반복 출력하지 않는다.
- 수치가 명백히 기준 미달이면 깊은 본문 수집을 중단한다. 적합 수치 후보만 날짜·주제·대화 검증으로 진행한다.
- 긴 AX/DOM/DM 전체 출력을 반복하지 않는다. 공개 후보는 ID·팔로워·6개 수치·실패 이유 중심으로 출력하고 세부 근거는 실행 파일에 둔다.
- 스크린샷은 실제 시각 검증이나 완료 증거가 필요할 때 사용한다.
- 검증된 1분 발송 간격 동안 다음 후보의 읽기 작업을 진행한다. 발송 결과 확인 전에는 다음 사람에게 전송하지 않는다.
- 후보 한 명당 사용량·절감률을 측정 없이 단정하지 않는다.

## 복구 가능한 실행

브라우저 탭 ID·변수명·현재 날짜를 스킬에 고정하지 않는다. 도구가 알려준 기존 브라우저와 탭을 재사용하고, 오래된 탭만 교체한다. 복구에 필요한 초기화 안내를 따른다.

긴 REPL 호출이 시간 제한을 넘으면 상태가 사라질 수 있다. 약 3~4개의 짧은 읽기 작업씩 나누고, 수집 관찰과 큐를 각 묶음마다 저장한다. 휘발성 변수에만 인원·후보·전송 상태를 두지 않는다.

체크포인트에는 KST 날짜, 오늘 목표·확정·수동 신규 수, 미확정 전송, 현재 후보의 검증 범위, 원장·공개 근거 파일, 다음 행동을 남긴다. 복구 후에는 저장된 원장과 현재 화면부터 대조한다. 시도 기록이 있으면 결과를 확인하기 전 다시 보내지 않는다.
