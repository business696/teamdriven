# 수락·주소·메이드·CS

## 분류와 답변

- 제품제공 조건을 수락하고 주소를 준 경우: 기존 답변 여부와 이후 조건·거절을 확인한다. 미발송이며 사용자가 회신을 요청한 범위면 address-guide.txt를 그대로 보낸다.
- 유가만 진행, 원고료 문의, 조건 질문, 주소와 유가 질문이 함께 있는 경우: 자동 수락으로 처리하지 않는다. 별도 목록에 남기고 임의 답장 없이 안읽음으로 복원한다.
- 조건 안내 뒤 상대가 명확히 수락하고 주소를 주면 당시 미확정 분류를 갱신할 수 있다. '주소가 있다'는 사실만으로 협업 확정을 추정하지 않는다.
- 긍정 답변만 있고 배송정보가 없으면 주소 미확보로 남긴다. 제품 테스트 후 마켓 검토는 무가 릴스 확정과 구분한다.
- 과거 가이드 발송 뒤 새 거절·활용 조건 이견이 있으면 최신 상태가 우선한다. 기존 가이드를 다시 보내지 않는다.
- 스크립트를 보여달라는 요청에는 저장된 승인 원문을 보여준다. 새 초안·요약으로 대체하지 않는다.

## 오늘 메이드 집계

수락일, 주소 수신일, 연락처 수신일, 가이드 발송일, 최종 상태를 각각 확인한다.

- 오늘 처음 확정된 건, 오늘 배송정보가 완성된 건, 이전 주소 수신 후 오늘 가이드를 전달한 건을 구분한다.
- 이전 확정자의 오늘 감사 인사·배송 안내만으로 신규 메이드를 늘리지 않는다.
- 유가·기한·수량·2차 활용 등 조건이 미확정이면 확정 인원과 분리한다.
- 수령인 이름은 배송정보 원문을 따른다. 공개 닉네임을 수령인으로 대체하지 않는다. 주소의 누락 필드·행정구역을 추정해서 채우지 않는다.
- 제품 출고·배송 완료는 별도 근거 없이는 완료라고 쓰지 않는다.

## Slack 게시를 요청받은 경우

사용자가 지정한 채널과 제목을 확인하고 기존 동일 날짜 스레드가 있는지 읽어 중복 생성을 피한다. 새 스레드를 요청했으면 제목을 원문대로 부모 메시지로 만든다.

요청한 범위의 확정 인원에 한해 각각 댓글로 ID·프로필 링크·수령인·연락처·주소·실제 진행 상태와 날짜를 올린다. 조건 미확정자와 테스트 검토자의 개인정보를 확정 명단으로 게시하지 않는다. 댓글을 채널에 별도 방송하지 않는다. 원문 수령정보를 필요 이상으로 고치지 않는다.

부모 timestamp와 각 댓글 ID·링크를 저장하고 스레드 재조회로 실제 게시 인원과 필드를 확인한다. 타임아웃 시 기존 스레드를 확인한 뒤 재개한다. 사용자에게는 스레드 링크와 집계 기준을 짧게 보고한다.

이 스킬 호출만으로 특정 채널에 개인정보를 게시할 권한이 생기지 않는다. 현재 요청에서 데이터와 게시 대상이 승인됐는지 확인한다.

## 최근 기간 CS 취합과 Notion

- 사용자가 요청한 기준일과 기간을 명시한다. 작업 중 날짜가 바뀌었다고 원래 기간 시작을 몰래 바꾸지 않는다.
- 목록 수집, 본문 검토, 이전 이력 검토, 확정 CS, DB 등록을 별도로 집계한다. 표시명 목록을 고유 계정 수로 단정하지 않는다.
- 최근 메시지만 읽지 말고 최초 제안·조건 변경·주소·가이드·후속 답변 등 관련 이전 이력을 확인한다. 가상화로 빠진 구간은 미검토로 남긴다.
- 경품 이벤트 배송, 유가 정산, 마켓 협의와 무가 릴스 CS를 문맥으로 구분한다.
- 사용자가 지정한 Notion DB를 fetch해 실제 속성·유형을 확인한다. 일상적인 기록 추가에 DB 재설계를 끼워 넣지 않는다.
- 실제 상대 문의, 실제 담당자 답변, 다듬은 답변, 현재 상태, 후속 조치, 출처·확인 시각을 구분한다. 다듬은 문장을 실제 발신으로 기록하지 않는다. 미답변이면 미답변으로 남긴다.
- 이력 추출·답변 다듬기 요청은 DM 발송 권한이 아니다. 고정 신규·주소 답변 스크립트 변경 권한으로도 해석하지 않는다.
- 쓰기 후 재조회해 빠진 계정과 유형, 중복·오분류를 확인한다. 현재 취합분 등록 완료를 기간 전체 전수 완료라고 보고하지 않는다.

## 안읽음 복원

1. 대화를 열기 전에 받은편지함 행에서 Unread 여부를 확인해 저장한다.
2. 검토 후 해당 대화에서 이탈한다. 일반 대화 행의 '옵션 더 보기 → 읽지 않음으로 표시'를 실행한다.
3. 메뉴 클릭만으로 완료라 하지 말고 실제 목록의 Unread 유지까지 확인한다. 동시 담당자가 답장한 후 읽음 상태를 무작정 반복해서 덮어쓰지 않는다.
4. 일반 대화 기능을 요청함에도 된다고 단정하지 않는다. 요청을 수락하지 않고 복원이 불가능하면 정확한 계정과 미완료 사실을 남긴다.
5. 로컬 안읽음 표시는 상대에게 이미 전달된 읽음 확인을 되돌리는 기능으로 설명하지 않는다.
