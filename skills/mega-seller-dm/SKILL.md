# 메가셀러 DM 컨택

사용자의 요청에 따라 후보 등록, 컨택 이력 조회, 초안 또는 발송을 처리한다. **어사이드(Aside)에서 Meta Creator Marketing Hub(마케팅허브)로 컨택**하고, Notion은 **API**를 사용한다. 어사이드는 접속 브라우저, 마케팅허브는 실제 컨택 채널이다. 일반 Instagram DM으로 대체하지 않는다. 스킬 설치는 브라우저 연결·로그인·발송 권한을 자동 부여하지 않는다.

## 첫 실행

먼저 [references/setup.md](references/setup.md)를 읽는다. 설정이 없거나 기존 설정에 `creator_marketing_hub_url`이 없으면 짧은 대화로 보완하거나 `python3 scripts/setup.py`로 저장한다. 실행마다 설정한 브랜드·발신 계정과 허브에서 선택된 비즈니스·페이지·Instagram 계정이 일치하는지 확인한다. 기존 프로젝트의 페르소나·업무 현황·최신 확정 스크립트가 있으면 우선 적용한다. 설정 파일은 업무 환경을 지정할 뿐 새로운 발송 승인이 아니다.

## 요청 범위

- `리스트/안 간 건 확인`은 조회만, `초안/컨택 문구`는 초안만이다. `보내줘/이어서 발송`은 지정 대상과 확정 문구의 발송 요청이다. 스킬 설치 요청으로 실제 DM을 보내지 않는다.
- 이미 승인된 동일 대상·문구는 다시 승인받지 않는다. 새 대상·다른 문구로 임의 확대하지 않는다.
- Git 저장소에는 실제 후보 명단·연락처·주소·DM 로그·인증 정보를 넣지 않는다. 실행 로그와 설정은 스킬 폴더의 `.local/` 또는 사용자 지정 비공개 위치에 둔다.

## 어사이드 연결 확인

1. 현재 제공된 도구와 문서에서 Aside의 실제 접근 경로를 확인한다. 과거의 연결 상태, 예시 메서드 또는 앱 실행 여부만으로 백그라운드 제어가 가능하다고 단정하지 않는다.
2. 사용자 Chrome으로 대체하지 않는다. 화면 방해 금지 설정이면 창 활성화·마우스 이동·탭/프로필/페이지 전환을 하지 않는다. `visible:false`만으로 화면 방해가 없다고 가정하지 않는다.
3. Aside가 앱으로만 보이고 백그라운드 탭 제어를 제공하지 않으면 지원하지 않는 API·포트·메서드를 만들어 쓰거나 쿠키·토큰으로 우회하지 않는다. 필요한 연결 또는 허용 방식만 안내한다.
4. 실제 발신 계정과 마케팅허브 컨택 이력을 읽을 수 없으면 `허브 이력 확인 필요`로 남긴다. 조회 불가를 미컨택으로 바꾸지 않는다. 후보 등록·초안 등 독립 작업은 계속한다.

## 마케팅허브 컨택

실행 전 [references/marketing-hub.md](references/marketing-hub.md)를 읽는다. 설정한 허브에서 크리에이터 계정 검색 → 정확한 대상·기존 이력 확인 → 허브 메시지 작성 → 승인된 발송 → 실제 완료 증거 확인 순서로 처리한다. 허브 검색에 안 나오거나 메시지 기능이 없으면 `허브 컨택 불가/확인 필요`로 분리한다. 일반 Instagram DM·이메일로 우회하지 않는다. 프로젝트 초대만 가능한 화면에서 금액·일정·의무 콘텐츠 등을 임의 입력하지 않는다.

## 후보와 미컨택 판정

이름·정규화한 Instagram ID·YouTube 핸들·타 플랫폼 링크를 대조한다. 점·밑줄은 보존하며 이름만 같은 사람은 합치지 않는다. 공식 Instagram 계정이 확인되지 않으면 추정 계정에 보내지 않는다.

등록 전 Notion DB와 일자별 전체 리스트를 확인한다. 새 YouTube 후보는 별도 유형 지시가 없으면 `3. 유튜브 브이로그 2030`이다. 기존 명시 유형과 발송·회신 이력은 유지한다. DB 등록 → 한국시간 당일 리스트 → 최신 초안을 한 묶음으로 처리하고 `답변·단가 현황`은 리스트 맨 아래에 둔다.

| 관찰한 근거 | 판정·처리 |
| --- | --- |
| 허브 발신 브랜드와 정확한 수신 계정의 발신 메시지·초대 이력 존재 | 허브 컨택 이력 있음. 새 문구로도 자동 재발송하지 않음 |
| 정확한 대상의 허브 이력 부재 확인 및 다른 채널의 기존 컨택 근거 대조 | 허브 미컨택 확인. 다른 채널은 확인한 범위만 명시 |
| 허브 검색 결과 없음·일부 목록만 조회·읽기 실패·DB 발송 0 | 허브 이력 확인 필요. 미컨택 확정 금지 |
| 전송 중·오류·클릭 후 결과 불명 | 발송 확인 필요. 재발송 전에 실제 대화 확인 |
| 과거 무가/유가 제안만 있고 마켓 이력이 불명 | 기존 컨택 있음 / 마켓 이력 확인 필요 |

거절·단순 선물 불가·경쟁사 계약 등 확인된 조건은 일반 일괄 발송에서 분리한다. 재컨택은 사용자가 지시한 대상만 처리한다.

## 확정 문구

[assets/dm.txt](assets/dm.txt)를 읽고 이름과 설정된 담당자만 치환한다. `python3 scripts/render_dm.py --name '크리에이터명'`은 텍스트만 출력하며 발송하지 않는다. 특징 메모를 그대로 붙이거나 원문을 임의 축약하지 않는다. 브랜드·제품 소개 링크가 포함된 원문을 유지한다. 링크를 빼거나 이메일 주소 요청 문구로 대체하지 않는다.

문구의 제품 수치·매출 사례는 사용자 확정 영업 문구이며, 이 스킬이 독립 검증한 사실이 아니다. 새 숫자·보장·의학적 주장을 추가하지 않는다. 다른 브랜드나 제품에 그대로 전용하지 말고 그 브랜드의 확정 문구를 먼저 받는다. 초안은 전체를 제공하고 `복붙` 요청은 설명 없이 text 코드블록만 제공한다.

## 발송·중단·재개

1. 현재 요청의 대상·문구·허브 발신 브랜드를 확인한다. 수신자별 실제 이력 확인 → 허브 메시지 입력 → 수신 계정·입력 본문 대조 → 발송 → 허브 대화·발신 기록과 완료 상태 확인 순서로 처리한다. 한 사람의 결과를 확인하고 다음 사람으로 넘어간다.
2. 클릭, 입력창 비워짐, `전송 중`만으로 완료 처리하지 않는다. 길이 제한으로 원문이 안 들어가면 임의 축약·분할 발송하지 않고 해당 건을 보류한다.
3. 로그인·보안 인증·계정 제한·전송 오류에서는 해당 발송을 멈춘다. 제한 우회·추정 대기시간 후 자동 재시도는 하지 않는다. 안전한 발송 건수·간격을 임의 보장하지 않는다.
4. 재개 시 완료·제외·발송 불명 기록부터 읽는다. 발송 불명은 실제 대화로 해소하고, 이미 보냈다면 DB 기록 실패만 복구한다. DM을 다시 보내지 않는다.

## 기록·보고

Notion 작업 시 [references/notion.md](references/notion.md)를 읽는다. 실제 발송 증거가 확보된 건만 횟수·최근 컨택일·상태를 반영한다. 사용자 `완`도 실제 발송 확인으로 보되 이번 배치와 중복 계상하지 않는다. 제품 발송은 실제 출고 확인 때만 기록한다.

이름·Instagram 링크·허브 프로필 또는 대화 링크(확인 가능한 경우)·판정·확인 근거와 함께 `대상 / 기존 컨택 있음 / 허브 미컨택 확인 / 허브 이력 확인 필요 / 실제 발송 완료 / 발송 불명 / 허브 컨택 불가 / DB 반영 실패`를 구분해 보고한다. 허브 이력과 일반 DM 이력을 혼동하지 않는다. 일부만 확인했다면 확인 범위를 밝힌다.
