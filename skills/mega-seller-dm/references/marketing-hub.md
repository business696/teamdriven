# Meta 마케팅허브로 컨택

## 사용하는 채널

컨택 채널은 **Meta Creator Marketing Hub(마케팅허브)**다. Aside는 이 허브에 접속하는 브라우저다. 일반 Instagram DM창에서 보내는 흐름으로 바꾸지 않는다. 화면의 메뉴·사용 가능 기능은 현재 계정에서 관찰한 상태를 따른다.

공식 맥락: [Meta의 브랜드·크리에이터 협업 안내](https://about.fb.com/news/2024/02/creator-marketplace-for-brands-and-creators-to-collaborate-on-instagram/)는 브랜드의 Meta Business Suite 참여와 Partnership Messages를 설명한다. [Meta의 허브 통합 안내](https://about.fb.com/br/news/2026/06/cannes-lions-2026-novas-ferramentas-criativas-e-de-criadores-para-todos-os-profissionais-de-marketing-cruzarem-a-fronteira-da-ia/)는 Creator Marketplace와 Partnership Ads Hub 통합을 설명한다. 이 자료는 모든 계정에서 현재 동일한 버튼·권한을 제공한다는 보장이 아니다.

## 접속과 발신자

- `.local/config.json`의 `creator_marketing_hub_url`을 사용한다. 로그인 후 사용자가 쓰는 허브의 실제 URL을 받는다. 다른 사람의 business/page/ad account ID를 하드코딩하지 않는다.
- 선택된 비즈니스, 브랜드 페이지, 연결 Instagram 계정을 실제 화면과 대조한다. URL만으로 로그인·발송 권한을 확인했다고 말하지 않는다. URL에 없는 ID나 이름을 추측하지 않는다.
- 로그인·계정 연결·필요한 권한 승인은 사용자에게 맡긴다. 새 약관 동의·계약·유료 광고 집행을 컨택 작업에 포함하지 않는다.
- 현재 도구가 제공하는 Aside 제어 범위와 화면 방해 금지 조건을 지킨다. 접속이 안 되면 원인·필요한 조치·미발송 상태를 알린다.

## 대상과 이력

1. 허브의 실제 검색 기능에 정확한 Instagram ID를 사용한다. 결과의 핸들·프로필·연결 채널로 동일인인지 확인한다. 이름만 비슷한 사람에게 보내지 않는다.
2. 해당 브랜드의 기존 대화·보낸 메시지·프로젝트 초대 등 현재 허브가 보여주는 컨택 기록을 확인한다. Notion과 기존 비공개 발송 기록도 대조한다.
3. 일반 DM·이메일의 기존 컨택 근거가 있으면 허브에 이력이 없어도 자동 신규 발송에서 제외한다. 사용자가 재컨택을 지시한 경우만 진행한다.
4. 허브에서 이력이 없다는 상태를 확인했으면 `허브 미컨택 확인`으로 기록한다. 일반 DM 전체까지 미컨택이라고 확대하지 않는다. 검색 결과 없음은 `허브 컨택 불가/확인 필요`다.

## 메시지 발송

- 정확한 대상의 허브 메시지/연락 기능이 실제로 제공될 때 사용한다. 버튼 이름·셀렉터·API는 현재 도구 문서와 화면에서 확인한다.
- `assets/dm.txt`를 읽어 이름·담당자만 치환하고 **브랜드·제품 소개 링크를 유지**한다. 발송 전에 선택된 브랜드·수신자·입력된 전체 본문을 대조한다.
- 프로젝트 초대만 제공되고 예산·보수·의무 콘텐츠·일정 등의 필수 조건을 요구하면 이를 임의로 만들지 않는다. 실제 사용자 조건이 없으면 해당 건을 보류해 필요한 항목만 요청한다. 조건이 명시된 초대와 일반 메시지를 같은 것으로 취급하지 않는다.
- 실제 전송 완료 표시, 허브 대화 내 발신 기록 또는 확인 가능한 성공 결과를 근거로 완료 처리한다. 클릭·닫힌 창·전송 중은 완료 증거가 아니다. 노출·전송 완료가 상대방의 읽음·수락·협업 확정을 뜻하지 않는다.
- 오류·제한·보안 인증이면 중단한다. 일반 DM으로 우회하거나 중복 재발송하지 않는다. 읽음·회신 확인 요청은 조회만 하고 자동 답장하지 않는다.

## 기록

비공개 실행 로그에 채널 `meta_creator_marketing_hub`, 실제 발신 브랜드/계정, 수신 IG ID, 확인 시각, 기존 이력 근거, 전송 완료/불명, 허브 대화 링크(있으면), DB 반영 여부를 남긴다. 인증 정보·전체 DM 로그를 GitHub에 올리지 않는다. Notion 기록 방식은 `notion.md`를 따른다.
