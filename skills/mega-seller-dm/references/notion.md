# Notion 기록

DB·일자 리스트 URL은 비공개 설정 또는 현재 프로젝트 문서에서 읽는다. datasource 스키마와 콘텐츠 수정 문서를 API로 먼저 읽고 정확한 속성명을 사용한다. 필드·식별자는 추측하지 않는다.

중복은 이름·Instagram ID·YouTube 핸들·비고 및 일자별 전체 목록으로 대조한다. ID는 URL 추적 파라미터·앞 @·끝 /를 제거하고 소문자로 비교하되 점·밑줄은 보존한다.

현 스키마가 아래 속성을 제공하면 사용하고, 다른 환경에서는 실제 스키마에 대응한다.

| 속성 | 입력 |
| --- | --- |
| 인플루언서명 / 한국어 닉네임 | 확인한 원문 이름 |
| 인스타그램 / 인스타그램 ID | 확인한 공식 계정. 미확인은 비우고 사유 기록 |
| 메가셀러 유형 | 사용자 지정. 별도 지시 없는 새 YouTube 후보는 3. 유튜브 브이로그 2030 |
| 협업 유형 | 메가 마켓. 기존 유형 보존 |
| 출처 | 새 후보는 신규 서칭 |
| 컨택 상태 / 메시지 발송 횟수 | 새 기록은 컨택 전 / 0. 실제 DM 미컨택의 증거가 아님 |
| 비고 / 진행 단계 | 원본 채널 링크·등록일·실제 이력 확인 여부·다음 행동 |

당일 리스트에도 같은 유형·링크·상태를 반영한다. `답변·단가 현황` 앞에 일자 항목을 넣고 기존 내역은 보존한다. 후보 등록일을 최근 컨택일에 넣지 않는다.

실제 발송 확인 후:
- 최신 DB 값과 비공개 실행 로그를 대조해 이번 확인된 발송만 횟수에 반영한다. 같은 이벤트를 재개·`완` 응답 때 두 번 더하지 않는다.
- 최근 컨택일은 실제 발송의 Asia/Seoul 날짜, 컨택 계정은 실제 발신 계정을 기록한다.
- 신규 발송은 회신 대기. 이미 회신받아 대화 중이면 회신 상태를 덮어쓰지 않는다.
- DM을 보냈다는 이유로 이메일 발송을 체크하지 않는다.
- 제품 발송·제품 발송일은 별도 출고 확인 때만 반영한다. 주소 수령만으로 변경하지 않는다.
- 배송 정보가 전달되면 해당 비공개 DB에 즉시 반영하고 제품 경험 후 마켓 협업 논의 액션을 남긴다. Git에 복사하지 않는다.

쓰기 실패 시 실제 발송 증거와 미반영 필드만 비공개 로그에 남겨 기록을 복구한다. DM은 재발송하지 않는다. API 응답과 경고를 확인하고 경고·충돌 또는 다음 단계에 정확한 저장값이 필요하면 재조회한다.
